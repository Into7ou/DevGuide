## 1. 产品定位

DevGuide 是一款面向开发者的「技术栈学习 Agent」Web 应用。用户查询某一技术栈，即可获得：

1. 该技术栈的**官方文档**入口；
2. GitHub 上该技术栈 **star 排行 Top 10** 的开源项目（作为学习资料）；
3. 基于上述资料的 **LLM 学习引导**（学习路线、概念讲解，带引用、可溯源）。

与普通搜索页的区别：Agent 不只是「检索 + 展示」，而是把「官方文档 + 优质开源项目」作为上下文，生成有据可依的学习建议。

## 2. 需求清单

### 2.1 核心功能（MVP）

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 技术栈查询 | 预置清单 + 自由输入具体技术栈名；新名称需确认属于真实的软件开发技术，非技术输入拒绝，不能确认时不收录 |
| F2 | 官方文档定位 | 静态映射表起步，新技术通过实体识别与联网证据核验官方归属后才转正；不得以任意仓库主页或搜索首条代替官网 |
| F3 | GitHub Top10 | 按 topic 搜索仓库、按 star 降序取前 10，展示卡片（star / 描述 / 语言 / 链接） |
| F4 | 学习对话 | 先检索本地 PGvector，由 Agent 判断资料缺口并按需联网；回答标注技术边界、来源与原文，支持保留和折叠历史轮次及连续追问 |
| F5 | 用户登录 | GitHub OAuth 登录，绑定 GitHub Token |
| F6 | 个人记录（预留） | 学习/查询历史，为后续个性化做准备 |

F4 主流程增强已实现：每问默认最多两轮联网补充，每轮一次搜索、最多三个正文页；仅对实际引用且由 Agent 选出的高价值原文异步回写，每问最多新增三个片段并复用重复内容。页面保留当前会话全部轮次，最近三轮已完成问答与引用用于追问上下文；刷新或切换技术栈清空。详见 [RAG 主流程增强需求](requirements/PRD-rag-main-flow.md) 与 [测试与验收](M6.5-动态转正与界面优化/测试与验收.md)。

### 2.2 非功能需求

| 编号 | 需求 | 说明 |
|---|---|---|

| N2 | 限流可控 | 用户各自绑定 GitHub Token，避免共享 Token 触发限流 |

| N5 | 容器化部署 | Docker Compose 一键起前后端 + 数据库 |

## 3. 技术选型

| 维度 | 决定 | 备注 |
|---|---|---|
| 改造基座 | **spring-ai-alibaba/examples（Apache-2.0）** | 官方示例：Playground + chat/RAG/tool-calling/MCP/agent 等模块 |
| 前端 | Vue3 | 复用 Playground 前端骨架 |
| 后端 | Java 21 + Spring Boot 3 + Spring AI Alibaba | 官方框架，Apache-2.0 |
| LLM | DeepSeek API | OpenAI 兼容协议 |
| RAG embedding | 阿里云通义 text-embedding | DeepSeek 不提供 embedding 模型 |
| RAG 范围 | v1 轻量（Top10 README + 关键文档页） | 预留全量文档扩展 |
| 业务数据库 | PostgreSQL | 与向量存储同库，简化部署 |
| 向量库 | PGvector（PostgreSQL 扩展） | Spring AI 一等公民，无需独立向量服务 |
| 登录鉴权 | GitHub OAuth（预留账号注册扩展） | |
| GitHub 凭证 | 用户各自绑定 Token（随 OAuth 授权） | |
| 部署 | Docker Compose 自托管 | |

## 4. 架构设计

### 4.1 总体架构

```
┌──────────────────────────────────────────────────────────┐
│                        Vue3 前端                          │
│   技术栈搜索/清单 · 文档+Top10 展示 · 学习引导对话         │
└──────────────────────────┬───────────────────────────────┘
                           │ HTTP / SSE
┌──────────────────────────▼───────────────────────────────┐
│            Spring Boot 后端（Spring AI Alibaba）          │
│                                                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌─────────┐ │
│  │ 认证模块  │  │ 检索模块  │  │ 文档模块  │  │ RAG 模块 │ │
│  │ OAuth2   │  │ GitHub   │  │ 映射表+  │  │ 切分+   │ │
│  │ Token绑定│  │ Search API│ │ 抓取     │  │ embedding│ │
│  └──────────┘  └──────────┘  └──────────┘  └────┬────┘ │
│                                                 │        │
│                    ┌────────────────────────────▼──────┐ │
│                    │        Agent 编排层（多智能体）      │ │
│                    │   DeepSeek 生成学习引导（带引用）    │ │
│                    └───────────────────────────────────┘ │
└──────────────┬────────────────────────────┬──────────────┘
               │                            │
        ┌────────────────────▼────────────────────┐
        │       PostgreSQL（含 PGvector 扩展）      │
        │     用户/业务数据 + RAG 向量索引          │
        └─────────────────────────────────────────┘
```

### 4.2 RAG 数据流

```
用户查「React」 / 追问「React Hooks 怎么入门」
        ↓
① 检索：GitHub API 拉 Top10 + 官方文档定位
        ↓
② 入库（RAG）：官方文档关键页 + Top10 README → 切分 → 通义 embedding → 向量库
        ↓
③ 生成：DeepSeek 基于检索片段生成学习路线/讲解（带引用、可溯源）
```

### 4.3 模块说明

- **认证模块**：Spring Security + GitHub OAuth2，登录后绑定/存储用户 GitHub Token。
- **检索模块**：调用 GitHub REST Search API（`/search/repositories?q=topic:<tech>&sort=stars&order=desc`），取前 10 条。
- **文档模块**：维护「技术栈 → 官方文档 URL」映射表；对每个技术栈抓取关键页（Getting Started / 核心概念页）。
- **RAG 模块**：文档/README 切分 → 通义 embedding → 向量库 → 相似度检索。
- **Agent 编排层**：M6 已实现 ReAct Agent 工具自主调用，以及 ResearchAgent 搜集资料 → GuideAgent 生成学习引导的两段式协作，前端使用 SSE 流式接口；保留 M3「入库 → 检索 → 生成」固定链路。MCP Server 已实现，MCP Client 默认禁用，外部接入演示待补充。

## 5. 数据模型草案

| 表 | 用途 | 关键字段 |
|---|---|---|
| users | 用户 | id、github_id、用户名、头像、创建时间 |
| user_tokens | GitHub Token 绑定 | user_id、access_token(加密)、scope、绑定时间 |
| tech_stacks | 预置技术栈清单 | id、名称、别名、官方文档 URL、简介 |
| query_history | 查询/学习记录（预留） | id、user_id、tech_stack、结果快照、时间 |
| doc_chunks | RAG 文档片段（预留全量） | id、tech_stack、来源 URL、文本、embedding |

## 6. 开发里程碑

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **M0 基座验收** | 验证 spring-ai-alibaba examples License → 摸清模块结构 → 确认本地环境 | License 合法（Apache-2.0）；环境可用；输出组装方案 |

| **M3 Agent 业务** | 检索聚合 + DeepSeek 学习引导 + 轻量 RAG 入库（同步固定链路） | 输入技术栈，输出带引用的学习引导 |

| **M6 Agent 化升级** | Function Calling（web 搜索 + GitHub 工具）+ MCP 接入 + ReAct Agent 自主编排 + SSE 流式 + 多智能体；支持任意技术栈动态搜索 | 自由输入任意技术栈，Agent 自主「搜索 → 查 GitHub → 检索 → 生成」并流式展示过程 |

| **M7 部署** | Docker Compose 编排 + 配置项 | 一键起前后端 + PostgreSQL(PGvector) |
| **M8 联调验收** | 端到端跑通、文档、交付 | 全流程可用 |

## 8. 风险与决策记录

| 风险/约束 | 说明 | 应对 |
|---|---|---|
| **License 硬门槛（已解决）** | careermate / yu-ai-agent 等候选均无开源许可 | 改用 spring-ai-alibaba/examples（Apache-2.0） |
| **DeepSeek 无 embedding** | DeepSeek 只提供对话模型 | 用阿里云通义 embedding 补齐 RAG |
| **基座定位** | 官方 examples 是「示例」而非完整业务 App | 复用骨架与示例组装，业务层自研 |
| **GitHub 限流** | 无 Token 60 次/小时 | 用户各自绑定 Token（5000 次/小时） |
| **全量文档 RAG 成本** | 全站爬取成本高、易碎 | v1 只做轻量 RAG，架构预留扩展 |

## 10. 文档约定与面试准备（贯穿全项目）

> 本项目目标之一是「可写进简历、面试可讲」。因此每个阶段除代码外，强制产出两类文档，均由我协助撰写与讲解。

### 10.1 每阶段文档

每个阶段（M0–M8）完成后，在 `docs/<阶段名>/` 下新建文件夹，包含：

| 文件 | 内容 |
|---|---|
| `问题记录.md` | 本阶段遇到的所有问题：现象 → 根因 → 解决方案 → 踩坑点 |
| `技术要点.md` | 本阶段涉及的关键技术栈/模块，用「是什么 → 在本项目中的作用 → 面试可讲点」三段式记录 |

### 10.2 面试准备

- 顶层 `docs/面试要点总览.md`：随开发持续汇总，形成一份「项目技术栈说明」，面试前可直接复习。
- 每阶段结束时，我会用通俗语言讲透该阶段的**关键模块与每个技术栈所起的作用**，确保你能回答「为什么用 Spring AI Alibaba」「RAG 解决了什么」「GitHub OAuth2 怎么登录并绑定 Token」这类问题。
- 目标不是「全部掌握」，而是「能说清每个技术栈在项目里的角色与选型理由」。
