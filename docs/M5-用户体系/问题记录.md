## 已解决的问题

### 1. 后端启动失败：`Hex-encoded string must have an even number of characters`

- **现象**：接入 OAuth2 + `TokenCipher` 后，后端启动时 `securityConfig` bean 创建失败，`Caused by: IllegalArgumentException: Hex-encoded string must have an even number of characters`。
- **根因**：`Encryptors.standard(key, salt)` 内部的 `DerivedSecretKeyGenerator` 会调用 `Hex.decode(salt)`，要求 salt 必须是**偶数长度的十六进制字符串**；原代码传的是普通字符串 `"techstack-agent"`（15 个字符，奇数），导致解码失败。
- **修复**：把固定盐值先转成 hex 再传入 —— `new String(Hex.encode("techstack-agent".getBytes(StandardCharsets.UTF_8)))`。密码 `key` 本身走 `PBEKeySpec`（PBKDF2），是作为普通口令使用的，不受 hex 限制，无需改动。
- **经验**：Spring Security 的 `Encryptors.standard/stronger` 的第二个参数是「hex 编码的盐」，不是任意字符串；填普通字符串会直接抛异常。

## 头像不显示问题（已定位）

- **现象**：登录后用户名正常，但右上角头像破图，控制台报 `Failed to load resource: net::ERR_CONNECTION_CLOSED`。
- **结论**：**网络环境问题，非代码 Bug**。后端返回的 `avatarUrl` 是 `https://avatars.githubusercontent.com/...`，该域名（GitHub 图片 CDN）在当前网络被屏蔽，直接访问 GitHub 官网图片也不显示。
- **处理**：前端加优雅降级 —— `AppHeader` 头像加载失败（`@error`）时显示用户名首字母圆形占位，避免破图。

### 甄别为「报告有误」的 1 项
- **M5**：审查建议把 `authentication` 强转为 `OAuth2LoginAuthenticationToken` 直接取 client。**这是错的**——success handler 收到的是 `OAuth2AuthenticationToken`，强转会 `ClassCastException`。现有 `loadAuthorizedClient` 写法在单实例下是标准且正确的。
