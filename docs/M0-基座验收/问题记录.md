# M0 基座验收 — 问题记录

> 阶段：M0 基座验收
> 结论：基座定为 spring-ai-alibaba/examples（Apache-2.0），环境就绪

---

## 问题 1：沙箱无法用 HTTP 直接访问 GitHub API / raw

- **现象**：`Invoke-RestMethod` / `Invoke-WebRequest` 访问 `api.github.com`、`raw.githubusercontent.com` 报「基础连接已经关闭」。
- **根因**：沙箱网络策略限制了 .NET HTTP 客户端请求，但 `git` over https 不受影响。
- **解决方案**：改用 `git clone` / `git ls-remote` 获取仓库，调研用 `web_search` 补充。
- **踩坑点**：不要用 .NET HTTP 客户端探测 GitHub，直接用 git 协议；star/License 等元数据拿不到时就靠 README 与 web 检索交叉验证。

## 问题 2：git clone 时 checkout 失败（Windows 非法文件名）

- **现象**：`fatal: unable to checkout working tree`，报 invalid path（文件名含 `>`，如 `tab-link-fail-面试题-->-AI.png`）。
- **根因**：`>` 是 Windows 文件名非法字符，Linux 允许，跨平台仓库落到 Windows 会 checkout 失败。
- **解决方案**：`git checkout HEAD -- . ":(exclude)<无关目录>"` 排除含非法文件名的目录（都是测试截图/媒体文件，与代码无关）。
- **踩坑点**：clone 报错但对象其实已下载；先用 `git ls-tree -r HEAD --name-only | Where-Object { $_ -match '[<>:"|?*]' }` 定位非法路径，再针对性 exclude。

## 问题 3：careermate 无 License（硬门槛）

- **现象**：仓库无 LICENSE 文件，README 写「开源许可证以后续仓库治理为准」。
- **根因**：未授予任何开源许可 = 默认「保留所有权利」，不能合法改造。
- **解决方案**：放弃 careermate，切换基座。
- **踩坑点**：README 里写「开源」≠ 有 License；改造前必须确认 **LICENSE 文件 + 具体协议**，而不是只看 README 声明。

## 问题 4：AI-Super-Agent-Project License 存疑

- **现象**：README 写「MIT」但仓库无 LICENSE 文件；且它是 yu-ai-agent 的换名拷贝。
- **根因**：个人项目许可不规范，README 声明没有法律文件背书。
- **解决方案**：放弃。

## 问题 5：yu-ai-agent 无 License

- **现象**：无 LICENSE 文件、README 无 License 声明，实为付费教学项目的营销仓库。
- **解决方案**：放弃；最终选定 spring-ai-alibaba/examples（Apache-2.0，已核实 LICENSE 文件内容为 Apache License 2.0）。

## 问题 6：spring-ai-alibaba/examples 同样有非法文件名

- **现象**：clone 时 checkout 失败，非法路径为视频示例的中文 mp4、RAG 示例的 html（`阿里云百炼.html`）。
- **根因**：同问题 2（Windows 文件名限制）。
- **解决方案**：这些是示例媒体文件，与我们无关，忽略；代码主体已正常检出。

## 问题 7：本地缺 pnpm 与 psql

- **现象**：`pnpm`、`psql` 命令不存在。
- **影响**：Playground 前端用 pnpm（可用 npm 替代）；psql 仅本地连 PG 用（可用 Docker 容器内 psql，且后端 Flyway 会自动建表，不强制需要本地 psql）。
- **解决方案**：前端改用 npm；数据库通过 Docker Compose 起 PostgreSQL，无需本地 psql。

---

## M0 结论

- **基座**：spring-ai-alibaba/examples（Apache-2.0，合法可用）。
- **环境**：JDK 21 / Maven 3.9 / Node 25 / Docker 29 就绪。
- **运行验证**：推迟到 M1（先搭建自有项目 + 起 PostgreSQL 后再跑通，因为跑官方示例需先配 LLM 密钥与数据库）。
