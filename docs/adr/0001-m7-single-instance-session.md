# ADR-0001：M7 首次部署采用单后端实例

> 决策日期：2026-09-04
> 状态：已接受
> 更新日期：2026-09-04

## 背景

当前登录状态保存在本机 HttpSession，OAuth authorized-client 也没有持久化为多实例共享状态。若直接部署多个后端副本，请求落到不同实例时可能丢失登录态或用户 GitHub Token。

## 决策

M7 首次部署只运行一个后端实例。反向代理不得把同一环境连接到多个 DevGuide 后端副本，部署文档与生产 profile 明确记录这一边界。

## 理由

首次部署目标是验证完整生产链路，单实例能保留现有 OAuth 行为并减少同时引入的故障变量。当前容量目标尚不要求横向扩容，因此暂不在本轮加入共享会话基础设施。

## 影响

- 后端重启会使现有会话失效，用户需要重新登录。
- 不能通过增加后端副本横向扩容。
- PostgreSQL/PGvector 仍使用持久卷，不受会话重启影响。
- 横向扩容前必须引入 `spring-session-jdbc`（或等价共享 Session）与 JDBC `OAuth2AuthorizedClientService`，并增加多实例登录回归测试。
- M7 的生成配额与并发状态同样只允许单实例内存实现，但必须通过可替换准入边界接入；横向扩容时将状态迁移到 Redis 等共享存储，并可在准入后增加任务队列。
