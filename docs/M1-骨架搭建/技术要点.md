# M1 骨架搭建 — 技术要点（面试可讲）

> 每个点用「是什么 → 作用 → 为什么」三句话讲清，点到为止。

## 1. Spring AI Alibaba（AI 框架层）
- **是什么**：Java 侧接入大模型的框架，统一抽象「对话模型 / 向量模型」。
- **作用**：接入 DeepSeek（对话）和通义（embedding）都走它，代码不绑定具体厂商。
- **为什么**：换模型只需改配置，不用改业务代码。

## 2. 对话模型和向量模型的分工
- **是什么**：对话模型负责生成文本；向量模型（embedding）负责把文本转成向量。
- **作用**：DeepSeek 生成学习引导；通义把文档转成向量（RAG 用）。
- **为什么**：DeepSeek 只提供对话、不提供 embedding，所以向量化用通义补齐。

## 3. 多模型共存怎么不冲突
- **是什么**：一个应用同时有多个模型时，注入泛型接口会报「多个 Bean」歧义。
- **作用**：注入具体类（如 `DeepSeekChatModel`）而不是泛型 `ChatModel`。
- **为什么**：这是 Spring 多 Bean 场景的标准解法之一。

## 4. 密钥外置（不硬编码）
- **是什么**：API Key 放 gitignored 的 `.env`，配置里用 `${VAR}` 占位符读取。
- **作用**：密钥不进代码库、不写死，防泄漏。
- **为什么**：代码一旦推到 GitHub，硬编码的 key 就等于公开了。

## 5. PGvector（向量存储）
- **是什么**：PostgreSQL 的向量扩展，能存向量并做相似度检索。
- **作用**：RAG 的「向量库」，一个 PostgreSQL 同时管业务数据和向量。
- **为什么**：少一个独立向量服务，部署最简。

## 6. 技术栈作用一览
| 技术 | 作用 |
|---|---|
| Java 21 + Spring Boot 3.5 | 后端应用基座 |
| Spring AI Alibaba | 统一接入 DeepSeek + 通义 + PGvector |
| DeepSeek（deepseek-chat） | 对话 / 学习引导生成 |
| 通义 text-embedding-v2 | 文本向量化（1536 维） |
| PostgreSQL + PGvector | 业务数据 + 向量检索 |
| Vue3 + Vite | 前端骨架 |
