## RAG 主流程与连续学习对话（2026-09-03 增强）

- **是什么**：每次学习问答先检索本地 PGvector；Agent 根据问题关键点判断证据缺口，再执行有限联网补充，最后生成有引用的答案。
- **在本项目中的作用**：`MultiAgentService` 保证检索次序和预算；`ResearchAgent` 判断充分性、挑选页面及原文；`GuideAgent` 讲解；`RagKnowledgeService` 检索与精选回写。沿用现有 DeepSeek、Tavily、Jsoup、PGvector 和 Reactor，不引入新平台。
- **可解释的技术价值**：检索发生在哪一步、答案用了哪份原文、哪些资料来自本地、哪里仍有缺口，用户都能从对话中核对。技术栈清单收录与学习资料入库是两个不同过程。

### 执行与引用

跨栈检索 topK=5、相似度下限 0.2；技术栈作为查询上下文，不做精确名称过滤。相似度负责找相关片段，Agent 负责判断问题覆盖程度。

每问默认两轮补充，每轮一次搜索、最多三个正文页；通过 `RAG_MAX_WEB_ROUNDS`、`RAG_MAX_PAGES_PER_ROUND` 可配置。每页向模型提供最多 24000 字符正文，按问题最多选四段连续原文、每段不超过 2000 字符。搜索摘要只用于选页；逐字片段必须在已取得正文中存在。链接和标题来自实际抓取结果，引用编号由服务端分配。

回答中实际出现的有效引用编号决定展示和回写候选；所有已取得资料并不会自动入库。完成事件发出后，使用 `boundedElastic` 异步筛选与 embedding，每问最多新增三个有后续参考价值的片段。稳定内容 ID 防止同一原文并发重复新增；后台查询也跳过被已有正文完整包含的片段，不删除原有向量。

### 页面会话

SSE `data` 使用 `{type,data}`：`status`、`scope`、`answer`、`sources`、`clarification`、`done`、`error`。旧单 Agent 字符串 SSE 解析保持兼容。

真实联调发现 SSE 写线程逐条请求与阻塞式资料搜集共用调度线程时，进度事件会积压到搜集结束。`subscribeOn(boundedElastic, false)` 让下游请求直接传递，阻塞工具仍在后台执行；使用模型尚未返回时必须收到检索进度的回归验证修复。

2026-09-04 的 M7 前置加固进一步为流式链路补齐登录上下文传播和清理，并把同一阻塞边界覆盖到单 Agent 流式入口。学习对话 POST 现要求登录和 CSRF Token；这属于上线安全边界更新，不改变 M6.5 的问答与引用协议。

页面内存保留全部轮次，折叠只影响展示；最近三轮完成问答和引用作为下一问上下文。切栈或卸载取消旧请求，刷新后重新开始；不创建持久会话表。断流保留部分输出并标为未完成，失败轮次不混入完成上下文。

原文去重属于异步写入检查，当前使用文本包含查询；不等于语义去重，也不保证长期大库性能。现有 HNSW 索引继续保留，实测样本及局限见验收文档。

## 1. 技术栈清单「动态转正」（自增长机制）
- **是什么**：未收录的技术栈在首次查询时，先识别具体技术实体并核验官方来源，通过后写入数据库成为正式记录，之后不再重复发现。
- **作用**：清单从「人工维护 21 条」变成「种子 + 用户驱动自增长」，覆盖任意技术栈而不需要人工填表。
- **为什么**：技术栈数量无穷无尽，人工预置永远不全；让用户查询行为反过来丰富数据，是「冷启动 + 自增长」的经典模式，面试能体现系统设计思维。

## 2. 官网发现：先确认归属，再核验检索证据
- **是什么**：实体识别给出待核验的官方归属；Tavily 搜索实际资料，按官方站点/项目路径筛选，模型依据标题与摘要选择来源下标。
- **作用**：入库 URL 必须来自实际候选，且经过身份与发布者归属核验，避免无关项目主页被当成官网。
- **为什么**：搜索相关度、GitHub 星数、URL 格式都无法单独证明官方身份。没有可靠证据时返回 503，不退回任意链接。C 的短名称使用人工核验映射，官方入口为 WG14。

## 3. 技术栈准入与分类分开
- **是什么**：识别结果明确区分 verified、not_tech_stack、uncertain；只有真实且具体的开发技术才进入分类与来源核验。
- **作用**：非技术返回 400，核验失败返回 503；只有名称、类型、分类和官方证据完整通过后才 upsert。GitHub Top10 放到准入之后查询。
- **为什么**：相关仓库的 topic 不能证明输入本身是技术；四选一分类会迫使食物等输入获得分类。模型或搜索异常也必须阻止入库，不能被成功降级掩盖。

分类由项目已接入的 DeepSeek Agent 根据主要用途和生态判断，四类含义集中在 `TechStackDiscoveryService.CATEGORY_PROMPT`。新技术在已有实体识别调用中分类；C 等已确认实体通过 `classify` 取得分类。前端 `categories.js` 只定义标签，`filterByCategory` 只筛选数据，不判断技术属性。现有 25 条分类已由相同方法复核一致。

## 4. 幂等转正：ON CONFLICT 原子 upsert
- **是什么**：用 PostgreSQL 的 `INSERT ... ON CONFLICT DO UPDATE` 实现「存在则更新、不存在则插入」的原子操作。
- **作用**：并发首次查询同一技术栈不会插入重复行；`COALESCE` 保证新值为 null 时不覆盖已有值。
- **为什么**：check-then-insert 有竞态（两个请求都判断「不存在」然后都插入）；数据库原子 upsert 是并发安全的标准解法。

## 5. 大小写不敏感唯一约束（LOWER 表达式索引）
- **是什么**：用 `CREATE UNIQUE INDEX ... ON tech_stacks (LOWER(name))` 让 "Next.js" 和 "next.js" 视为同一记录。
- **作用**：查找是大写不敏感的（`LOWER(name)=LOWER(?)`），唯一约束也要匹配，否则会插入大小写变体重复行。
- **为什么**：唯一约束必须和查询语义一致，否则「防重复」失效；这是数据库层一致性设计。

## 6. 侧边栏三通道交互（hover + 点击 + 键盘）
- **是什么**：侧边栏支持 hover 呼出（桌面）、点击锁定展开（触屏无 hover）、键盘 Tab+Enter 可达。
- **作用**：同一交互覆盖桌面、触屏、无障碍三种场景。
- **为什么**：hover 在触屏设备上不存在，只靠 hover 会把触屏用户挡在门外；多通道交互是无障碍（a11y）的基本要求。

## 7. 前端单一数据源（categories.js）
- **是什么**：分类的 4 个值（frontend/backend/ml-data/infra）集中在一个 `categories.js` 常量文件，侧边栏和首页筛选共用。
- **作用**：避免同一份数据在多处重复定义、漂移后不一致。
- **为什么**：多组件复用时单一数据源（single source of truth）是消除重复代码、降低维护成本的核心原则。

## 8. 技术栈作用一览
| 技术 | 作用 |
|---|---|
| PostgreSQL `ON CONFLICT` | 原子 upsert 转正 |
| 表达式唯一索引 `LOWER(name)` | 大小写不敏感防重复 |
| Tavily | 提供可核验的官方来源候选 |
| DeepSeek | 技术实体识别、分类、官方来源语义核验 |
| GitHub Top10 | 准入通过后的开源项目资料；homepage/topics 不承担准入证明 |
| Flyway V7 | 保留原主键，定向修复 C语言 的旧错误数据 |
| Vue hover/click/keyboard | 侧边栏三通道交互 |
