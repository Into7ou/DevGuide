## 本轮目标

1. **F2 补全**：未收录技术栈（如 Next.js）首次查询时，自动发现官方文档并转正入库，之后成为正式记录。
2. **侧边栏**：左侧 hover 呼出 + 点击锁定 + 键盘可达的分类导航。
3. **首页**：从「写死 21 条」变「种子 + 动态转正」，加分类筛选。

## 关键设计决策（讨论结论）

- 动态转正采用**同步**方式（首次查询本就要等，多 2-4 秒无感，逻辑简单）。
- 分类判定：**GitHub Topics 规则映射优先，DeepSeek 兜底**（控制 LLM 调用成本）。
- 官网发现：**GitHub homepage 字段优先，Tavily 联网搜索兜底**。

## 对抗性审查发现的问题与修复

### 🔴 P0（阻断级）：转正记录缺 `github_search_query` → 第二次访问 Top10 永久为空

- **现象**：首次查未收录技术栈正常（内存里返回刚拉取的 repos），但转正入库的新行 `github_search_query` 为 NULL，第二次访问命中该行后 `fetchTopRepos` 对 null 直接返回空列表 → 详情页「暂无项目数据」，学习引导也无法入库。
- **修复**：`upsertDiscovered` 增加 `github_search_query` 列并传入 `name + " in:name,description"`；同时 `fetchTopRepos` 加防御性兜底（query 为空时按名称派生）。
- **验证**：Nuxt 第 1 次和第 2 次访问 topRepos 都为 10。

### 🟡 P1：ON CONFLICT 大小写敏感 → 并发首查插入大小写重复行

- **修复**：V6 迁移加 `LOWER(name)` 唯一索引，`ON CONFLICT (LOWER(name))`。
- **验证**：查 "next.js" 命中已有 "Next.js"，清单无重复。

### 🟡 P1：零信息转正入库垃圾记录

- **修复**：官网与分类都为 null 时不落库（`docUrl != null || category != null` 才 upsert）。

### 🟡 P1：homepage/Tavily URL 校验过弱（放过 `http://`、非官网）

- **修复**：加 `isValidHttpUrl`（校验 scheme + host），Tavily 兜底优先选 hostname 含栈名的结果。

### 🟡 P1：LLM 分类子串误判（`html` 含 `ml`、`database` 含 `data`）

- **修复**：改为 `switch` 精确匹配英文 + 中文标签，非法输出返回 null。

### 🟡 P2：topic 元素 null NPE、精确 equals 命中率低

- **修复**：topic 判空 + 改为 `contains` 包含匹配 + 扩充常用 topic（nextjs/nuxt/go/rust 等）。

### 🟡 P2：name 未 trim 产生空白变体重复

- **修复**：`getOverview` 入口 `name.trim()` + 截断 100 字符。

### 🟢 P3：GithubRepoItemTest 未覆盖 homepage、分类三处来源无一致性校验

- **修复**：补 homepage 反序列化测试 + 新建 `TechStackDiscoveryServiceTest` 断言 VALID_CATEGORIES 与前端/V5 一致。
