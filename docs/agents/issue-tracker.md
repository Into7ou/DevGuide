# 问题记录：本地 Markdown

本项目的问题和需求文件使用本地 Markdown，统一保存在 `docs/` 下对应目录。

## 文件约定

- 新增专题需求文档：`docs/requirements/PRD-<feature-slug>.md`。
- 问题或实施任务：`docs/issues/<阶段或功能>/ISSUE-<NNN>-<slug>.md`，每个阶段或功能目录从 `001` 编号，创建前检查已有编号。
- 示例：`docs/issues/M6.5/ISSUE-001-stack-category.md`。
- 使用简短、可辨识的文件名；已有文件继续沿用原路径，更新前先检查以避免重复创建或覆盖无关内容。
- 问题文件顶部使用 `Status:` 记录状态，具体名称见 `triage-labels.md`。
- 已实现并完成与风险相称验收的问题使用项目终态 `done`，保留修复与验证记录，不删除历史问题文件。
- 问题文件包含现象或目标、预期与实际行为、复现步骤（适用时）、影响范围、验收标准和验证结果；根因未确认时明确标为待确认。
- 后续讨论追加在文件末尾的 `## Comments` 下。

## 技能操作的含义

- “发布到问题跟踪器”：在 `docs/requirements/` 或 `docs/issues/` 创建或更新上述 Markdown 文件。
- “读取任务”：读取用户指定的本地文件；仅提供编号时，先定位对应文件。
- “修改标签”：更新问题文件的 `Status:` 字段。
- 现有 `docs/需求确认书与开发计划.md` 保留为项目总需求；阶段问题记录和技术要点继续保存在原目录。具体任务文件与阶段总结按需互相引用，避免复制整份内容。
- Git 仓库和 GitHub 提交等待 MVP 可用后用户另行安排；本次配置仅建立本地文件约定。
