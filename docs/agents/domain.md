# 项目背景文档约定

## 布局

本项目采用单一上下文，前后端共用项目术语和架构决策：

- 根目录 `CONTEXT.md`：项目术语、业务概念和约定。
- `docs/adr/`：重要架构决策。
- `docs/需求确认书与开发计划.md`：产品需求、里程碑和当前开发状态。
- `docs/<阶段名>/问题记录.md` 与 `技术要点.md`：阶段实现、问题修复和技术说明。

## 使用规则

- 分析代码前，按任务范围阅读相关项目背景、需求、阶段记录和架构决策。
- `CONTEXT.md` 或 `docs/adr/` 尚未存在时，继续使用已有文档开展工作；无需仅为初始化创建空文件或要求用户补齐。
- 术语和决策形成明确结论后，由 `grill-with-docs` 等技能按需创建或更新背景文档。
- 输出中的业务概念沿用项目已有术语，避免为同一概念随意更名。
- 若方案与已有架构决策冲突，指出冲突和调整理由，不静默覆盖。
- 文档与实现不一致时，区分需求目标、历史记录和代码事实，不把历史测试结果当作本次验证。
- 现有阶段文档保留原位置；新文档通过引用关联已有资料。

## 文档目录规范

| 文档类型 | 位置 | 约定 |
|---|---|---|
| Agent 规则入口 | 根目录 `AGENTS.md` | 汇总规则并链接技能配置 |
| 项目背景入口 | 根目录 `CONTEXT.md` | 按需生成，前后端共用 |
| 总需求与开发计划 | `docs/需求确认书与开发计划.md` | 唯一总入口，持续更新状态 |
| 专题需求 | `docs/requirements/PRD-<slug>.md` | 明确目标、范围、非目标与验收标准 |
| 问题和实施任务 | `docs/issues/<阶段或功能>/ISSUE-<NNN>-<slug>.md` | 一项任务一个文件 |
| 阶段总结 | 现有 `docs/<阶段名>/` | 沿用 `问题记录.md` 和 `技术要点.md`；新增阶段采用 `M7-部署` 等相同命名方式 |
| 测试与验收 | 对应 `docs/<阶段名>/测试与验收.md` | 记录环境、步骤、预期、实际结果及未验证项；已有手动测试说明优先复用 |
| 架构决策 | `docs/adr/NNNN-<slug>.md` | 全项目连续编号，保留背景、选择、理由与影响 |
| 技能配置 | `docs/agents/` | 配置规范，不放业务问题或阶段总结 |

## 命名与内容规范

- 正文使用中文、UTF-8 编码；代码标识符、状态值及命令保持原文。
- `<slug>` 使用简短的小写英文连字符名称；既有中文文件名保留，不为格式统一批量改名。
- 需求、问题、阶段总结和验收文档顶部记录标题、所属阶段或功能、创建日期、更新日期；日期使用 `YYYY-MM-DD`。
- 需求与阶段总结写明实际状态；问题文件使用已确认的 `Status:` 状态名称，并单独记录修复或验收结果，避免将“可交给 Agent”当作“已修复”。
- 技能配置和项目背景入口保持精简，按需要记录更新日期；架构决策记录决策日期和状态。
- 使用 Markdown 相对链接关联文件；具体任务链接需求来源，阶段总结链接具体问题或验证记录。
- 同一主题以已有文档为准持续更新，避免 `最终版`、`最终版2` 等副本；需要保留历史时使用变更记录或注明被替代的决策。
- 文档内只记录已经确认的事实；拟议方案、待确认根因、未执行测试分别标明，不写成已完成。
- 里程碑变化时同步更新总需求文档中的状态和下一步，并更新对应阶段记录。
- 文档、示例和日志摘录不得包含密钥或 Token 原值；配置使用变量名或占位值。
- 目录按需创建，本次初始化不批量生成空需求、空问题、空架构决策或空背景文档。
