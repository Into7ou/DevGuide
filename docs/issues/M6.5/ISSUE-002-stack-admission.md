# 非技术输入可被自动收录为技术栈

所属阶段：M6.5 动态转正与界面优化
创建日期：2026-09-03
更新日期：2026-09-03
Status: done
Resolution: fixed
验收结果：非技术输入被拒绝、核验失败不入库，正常新技术栈仍可收录

需求来源：[总需求 F1/F2](../../需求确认书与开发计划.md)
关联问题：[官方来源误识别](ISSUE-001-official-source-validation.md)

## 现象、复现与影响

搜索食物等非技术输入时，只要 GitHub 找到相关软件，就会被当作技术栈分类、入库，污染首页清单。
固定复现：输入“红烧肉”，仓库只有 `backend` topic，即使没有 homepage，仍会调用 upsert。
预期：先确认输入本身是具体的软件开发技术，不能因存在相关软件就收录原输入。

## 已确认根因

- topics 描述的是返回的仓库，无法证明用户输入是技术栈。
- 分类提示词只有四个分类，没有非技术/不确定的出口。
- `docUrl != null || category != null` 是信息非空检查，无法承担技术栈准入。
- 广泛捕获发现异常并返回成功详情，会掩盖核验失败。

## 修复

- 新增独立的技术实体识别，限制为具体编程语言、框架、库、数据库、开发平台、开发工具或协议；明确区分 verified、not_tech_stack、uncertain。
- 输入和检索内容作为不可信 JSON 数据传递，提示词明确禁止执行其中的指令或把日常事物改写成相关软件。
- 实体类型、分类、规范名称、简介及官方来源必须完整通过核验后才允许 upsert；GitHub Top10 查询移至准入通过之后。
- 非技术返回 400；证据不足、模型格式错误或上游故障返回 503。异常不再降级为成功详情。
- 名称超长/含控制字符直接拒绝，避免截断后以另一名称入库；规范名称复用已有记录，保留大小写唯一约束。
- 前端显示后端的具体错误信息；失败状态不展示文档或学习入口。

## 验收与边界

真实调用中“红烧肉”“今天天气”、虚构框架名、要求绕过规则的输入均返回 400，未增加清单记录。
复验“红烧肉”前后均为 25 条，所有记录内容不变。Astro 正常首查收录且小写复查无重复。
模型异常、搜索失败、错误类型/字段和来源证据不足通过固定回归验证；详见 [测试与验收](../../M6.5-动态转正与界面优化/测试与验收.md)。

语义识别仍依赖模型和搜索质量，并非数学上的真实性证明。当前策略在不能确认时拒绝自动收录，可能暂时拒绝冷门或较新的真实技术；不扩大为自动清理所有历史数据。
