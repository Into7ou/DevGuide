## 问题与目标

旧页面的 ResearchAgent 自主选择工具，无法保证 PGvector 检索先行；联网结果只有摘要和 URL，没有可核对正文与后续复用。每次提交清空上一答，后端也没有收到追问上下文。

用户确认：本地检索必须纳入主流程，Agent 判断缺口后联网；明确跨栈边界、原文出处，并在回答完成后精选回写。每次追问独立获得联网预算，页面保留全部轮次、可折叠并显示分界。

## 实现

- `MultiAgentService` 固定先检索 PGvector，再由 `ResearchAgent` 判断充分性。每问默认最多两轮联网，每轮一次 Tavily 搜索、最多三个正文页。
- Agent 选择真实搜索候选、从 Jsoup 抓取正文中选择连续原文；服务端校验原文包含关系，从实际页面绑定标题、URL，并分配本轮引用编号。
- `GuideAgent` 按问题和资料生成答案，说明技术范围、第三方身份及仍存在的缺口。SSE 分别发送检索进度、范围、答案、引用及完成或错误事件。
- `RagKnowledgeService` 跨栈检索，复用现有向量表。仅在回答完成后对实际引用的联网片段执行 Agent 价值筛选及异步回写，每问最多三个；稳定原文 ID 与已有内容包含查询复用重复片段。
- `LearnPanel` 保留每轮提问、回答、原文卡片及检索过程。失败时保留已输出内容；发送最近三轮完成上下文，切栈取消旧请求并清空临时会话。

## 范围与限制

不增加数据库会话表、任务队列、整站抓取或 Git 操作。历史回答只帮助理解追问，不自动成为新一轮事实依据。旧的独立 `/learn`、单 Agent 接口继续保留，页面主流程使用 `/multi/stream`。

每问三个片段是增长约束，不是总容量上限；文本包含去重不是语义去重。身份与覆盖程度仍由模型判断，来源卡片用于人工核对。具体真实调用和性能样本见阶段验收。
