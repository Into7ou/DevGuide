# 不可变版本发布与回滚

所属阶段：M7 部署
创建日期：2026-09-04
更新日期：2026-09-05
Status: ready-for-human

## 目标

让 OCI 人工部署可追溯、可验证并能安全回到上一成功版本，同时避免可漂移镜像标签和不兼容数据库迁移造成伪回滚。

## 已确认方案

- 首次正式版本为 `v0.7.0`；前端和后端作为同一发布单元使用相同不可变标签。
- CI 为发布镜像同时生成版本标签和 Commit SHA 标签。
- 生产 Compose 要求显式设置 `IMAGE_TAG`，禁止依赖 `latest` 或 `main`。
- 每次发布先生成并确认数据库备份，再拉取镜像、更新服务、执行健康与关键路径检查，并记录成功版本。
- 仅当数据库迁移向后兼容时允许切回上一应用版本；不兼容迁移使用前向修复或恢复部署前备份。

## 实施范围

- 对齐前后端项目版本与 `v0.7.0` 首发标识，并配置 GHCR 版本/SHA 标签。
- Compose 镜像引用统一读取必填 `IMAGE_TAG`。
- 提供发布、验证和回滚命令清单，以及不包含敏感信息的发布记录模板。
- 在回滚步骤前设置 Flyway 兼容性确认门，避免机械执行旧镜像。

## 验收标准

- 同一次 CI 发布的前后端版本标签、Commit SHA 与镜像摘要可相互核对。
- 未提供 `IMAGE_TAG` 时生产 Compose 配置校验失败；提供 `v0.7.0` 时解析为两个同版本镜像。
- 在隔离环境完成一次发布及应用版本回滚演练，并记录健康检查结果。
- 模拟不兼容数据库迁移时，流程明确阻止单独回滚应用。
- 发布与回滚资料不含 API Key、OAuth Secret、数据库密码或 SSH 私钥。

## 验证结果

- 前后端版本已统一为 0.7.0；CI 配置版本标签与 Commit SHA 标签。
- 生产 Compose 缺少 IMAGE_TAG 时已验证拒绝解析；发布脚本只接受 vX.Y.Z 或 sha-...。
- 已实现“备份 → 拉取同标签前后端 → 更新 → 验证 → 仓库外记录”发布脚本、回滚兼容性硬门与发布记录模板。
- Bash 语法和拒绝门可本地验证；真实发布、镜像摘要记录及上一版本回滚演练需 GHCR/OCI 就绪后由用户完成，因此转为 ready-for-human。
