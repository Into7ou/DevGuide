# 生产日志脱敏与短期轮转

所属阶段：M7 部署
创建日期：2026-09-04
更新日期：2026-09-05
Status: ready-for-human

## 目标

保留足以排查公网部署故障的短期日志，同时避免用户内容、认证信息和密钥进入日志，并防止 OCI 单机磁盘被无限增长的容器日志占满。

## 当前风险

- `WebSearchTools`、`KnowledgeSearchTools`、`GithubTools` 和 MCP 工具会在失败时输出完整查询词。
- `TechStackService` 的 JSON 解析失败日志会输出原始 JSON。
- Compose 尚未配置日志大小轮转；Docker 默认日志行为可能长期占用磁盘。

## 已确认方案

- 生产默认日志级别为 `INFO`，关闭 SQL、Spring Security 等调试输出。
- 不记录完整提问、搜索词、查询参数、原始资料/JSON、Token、Cookie、OAuth 信息、API Key 或数据库密钥。
- 保留随机请求 ID、接口模板、状态码、耗时、错误类型和必要的非敏感业务标识。
- 每个服务的应用日志最多保留 7 天且总量最多 50 MB，任一上限先达到即清理旧日志。
- Docker 诊断日志使用受支持的日志驱动轮转；不直接操作 Docker 正在写入的底层日志文件。
- 日志不进入命名卷、数据库备份或对象存储灾备；未来多实例可迁移到 OpenTelemetry/Loki 等集中方案。

## 实施范围

- 清理现有输出查询词和原始 JSON 的日志语句，保留可定位错误的类型与请求 ID。
- 增加生产请求关联 ID，并确保客户端提供的 ID 不可造成日志注入或无限长度。
- 配置 Spring Boot 与 Caddy 的生产日志字段、脱敏和时间/大小轮转。
- 为 Compose 服务配置 Docker 日志大小轮转，生产与本地开发参数分离。
- 对频繁的 `/api/health` 探测日志进行安全降噪，不影响故障可见性。

## 验收标准

- 使用包含换行、伪造 Header、Token 形式和长查询词的请求验证日志脱敏与日志注入防护。
- 成功、4xx、5xx 和 SSE 异常均能以随机请求 ID 关联，且日志不出现请求正文或敏感 Header。
- 通过缩小测试阈值验证时间与大小两种轮转条件，旧日志自动删除且当前日志仍可写入。
- 生产日志总量有明确上限，本地开发配置和 Docker Desktop 日常使用不受影响。

## 验证结果

- 已清理工具、GitHub、Agent、OAuth 与全局异常日志中的查询、原始 JSON、Token、用户 ID 和异常消息。
- 后端生成或接收格式受限的代理 UUID，记录方法、无查询串路径、状态、耗时与错误类型；伪造/换行 ID 自动替换。
- Caddy 覆盖客户端代理 ID、删除访问日志请求 Header 与查询串、掩码 IP，并写入可关联 request_id。
- 后端 Logback 与 Caddy 应用日志均配置 7 天/约 50 MB 上限；三服务 Docker local 驱动配置 10 MB × 5。
- 自动化测试、Caddy 官方配置解析和真实容器查询串脱敏检查通过；生产磁盘上的时间/大小轮转仍待 OCI 长时运行或缩限演练，因此转为 ready-for-human。
