# 生产数据库加密备份与恢复

所属阶段：M7 部署
创建日期：2026-09-04
更新日期：2026-09-05
Status: ready-for-human

## 目标

为 OCI 单机 Compose 部署建立不依赖本机 Docker 命名卷的离机备份，使生产数据库在实例、卷或误操作故障后能够恢复，同时不把明文用户数据或解密私钥交给云主机、仓库或 CI。

## 已确认方案

- PostgreSQL 每日生成压缩逻辑备份；生产灾备包含全库，与首次上线时排除用户数据的脱敏迁移包严格区分。
- 在 OCI 实例上使用非对称公钥加密备份，只部署加密公钥；解密私钥由用户离线保管。
- 加密后的对象上传到私有 OCI Object Storage Bucket，保留 7 个日备份和 4 个周备份。
- Bucket 使用最小权限凭据，不公开，不通过 GitHub Actions 传递生产备份或凭据。
- 上传完成后删除本机临时备份；失败路径同样清理明文并返回失败状态。

## 实施范围

- 提供可审阅的备份、轮换和恢复脚本及环境变量示例，不提交真实密钥或 Bucket 凭据。
- 提供定时执行方式、日志检查方法和失败排查说明。
- 对对象命名、保留窗口、重复执行和不完整上传进行保护。
- 文档说明解密私钥的离线备份责任，以及密钥丢失会导致历史备份不可恢复。

## 验收标准

- 本地或隔离环境可以验证“逻辑导出 → 压缩 → 公钥加密 → 上传”的完整流程。
- 对象存储仅包含密文，主机临时目录不残留明文转储。
- 自动保留 7 个日备份和 4 个周备份，清理动作不会越过约定恢复窗口。
- 随机选择一个远端密文备份，使用离线私钥恢复到临时 PostgreSQL，并验证 Flyway 历史、核心表计数和 PGvector 查询。
- 备份或上传失败时退出码非零，日志足以定位失败步骤。

## 验证结果

- 已实现流式 pg_dump → age 公钥加密 → OCI Object Storage 上传脚本，不在主机落明文。
- 已实现 daily 保留 7 份、UTC 周日 weekly 保留 4 份的前缀内安全轮换，以及带显式破坏性开关的恢复脚本。
- 已提供最小环境模板、systemd oneshot/timer 与运行手册；Bash 语法检查通过。
- 尚待用户创建 age 离线密钥、私有 Bucket/最小权限凭据，并在 OCI 完成上传和随机密文恢复演练，因此转为 ready-for-human。
