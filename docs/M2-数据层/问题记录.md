## 问题 1：Flyway 启动失败（blocking，已修复）

- **现象**：后端启动报 `Found non-empty schema(s) "public" but no schema history table`。
- **根因**：M1 时 Spring AI 的 PgVectorStore 已自动创建 `vector_store` 表，`public` schema 非空；引入 Flyway 后它发现「有对象但无迁移历史表」，出于安全拒绝迁移。
- **解决**：`application.yml` 加 `spring.flyway.baseline-on-migrate: true` + `baseline-version: 0`。
- **踩坑点**：只设 `baseline-on-migrate` 而不设 `baseline-version: 0`，默认基线版本 1 会跳过 V1 迁移。

## 问题 2：Mockito 单元测试在沙箱里初始化失败（环境限制）

- **现象**：`Could not initialize inline Byte Buddy mock maker` / `Could not self-attach to current VM`。
- **根因**：Mockito 需要 ByteBuddy 自附加 Java agent（spawn 辅助进程），沙箱拦截。
- **解决**：`danger-full-access` 升级权限跑测试；4 个测试全部通过。
- **踩坑点**：沙箱限制，用户本机 `mvn test` 无此问题。

## 问题 3：GitHub `topic:` 搜索语义（设计注意点，非 Bug）

- **现象**：查 React，`freeCodeCamp`（45 万 star）排第一，而非 React 本体。
- **根因**：`topic:react` 匹配「打了 react 标签的所有仓库」，freeCodeCamp 使用 React 且 star 极多。
- **处理**：v1 接受；后续可优化相关性（结合 `in:name` 或排除「仅作为依赖」的巨型仓库）。

## 问题 4：postgresql 驱动 scope 导致编译失败（已修复）

- **现象**：`JsonbTypeHandler` 编译报「找不到 org.postgresql.util 包」。
- **根因**：postgresql 驱动设了 `<scope>runtime</scope>`（运行时有、编译时无），而 `PGobject` 编译期要用。
- **解决**：去掉 scope，改为默认 compile。
- **踩坑点**：写自定义 TypeHandler 用到驱动类时，驱动不能是 runtime scope。
