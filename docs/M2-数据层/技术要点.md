# M2 数据层 — 技术要点（面试可讲）

> 每个点用「是什么 → 作用 → 为什么」三句话讲清，点到为止。

## 1. MyBatis-Plus（ORM）
- **是什么**：MyBatis 的增强工具，`BaseMapper` 免写增删改查，复杂查询用自定义 SQL。
- **作用**：`tech_stacks` 表的查询（按名称、按别名）。
- **为什么**：国内主流、SQL 可控；比 JPA 更贴近手写 SQL。

## 2. Flyway（数据库版本管理）
- **是什么**：按版本号顺序执行 SQL，记录已应用过的迁移。
- **作用**：建 `tech_stacks` 表 + 21 个技术栈种子数据，换环境可自动复现。
- **为什么**：避免手动建表，数据库结构随代码一起版本化。

## 3. RestClient（调 GitHub API）
- **是什么**：Spring 6 的现代 HTTP 客户端。
- **作用**：调 GitHub Search API 拉取 star Top10。
- **为什么**：比老 RestTemplate 简洁，能自动把 JSON 反序列化成对象。

## 4. Caffeine + 缓存（应对限流）
- **是什么**：本地缓存 + `@Cacheable` 声明式缓存。
- **作用**：缓存 Top10 结果（24 小时有效），避免重复调用撞 GitHub 搜索限流。
- **为什么**：Top10 排名短期不变，缓存能大幅减少对外调用。

## 5. Jsoup（网页抓取）
- **是什么**：Java 的 HTML 解析库。
- **作用**：抓官方文档关键页，转成纯文本，供 RAG 用。
- **为什么**：只抓「关键页」不抓整站，成本低、够用。

## 6. GitHub Search API
- **是什么**：GitHub 提供的仓库搜索接口，可按 topic、按 star 排序。
- **作用**：拉某技术栈 star 排行 Top10。
- **为什么**：官方 API 最可靠，`topic:` 搜索最精准。

## 7. JSONB + 自定义 TypeHandler
- **是什么**：PostgreSQL 的 JSON 列类型；TypeHandler 处理「Java 类型 ↔ 数据库类型」转换。
- **作用**：存 `doc_key_pages`（关键页 URL 数组）。
- **为什么**：JSON 用 JSONB 存更规范；自定义 TypeHandler 保证写入时类型正确。

## 8. 技术栈作用一览
| 技术 | 作用 |
|---|---|
| MyBatis-Plus | tech_stacks 表 ORM |
| Flyway | 建表 + 种子数据版本化 |
| RestClient | 调 GitHub API |
| Caffeine + @Cacheable | Top10 缓存，应对限流 |
| Jsoup | 官方文档关键页抓取 |
| GitHub Search API | star Top10 检索 |
| JSONB + TypeHandler | 关键页存储与读写 |
