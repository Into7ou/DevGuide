## 本轮范围

验证部署前安全基线、公开展示访问、生成成本准入、生产容器、反向代理、脱敏迁移、短期日志、备份/发布脚本和单实例部署边界。

首次上线的产品目标是简历与面试展示：网站需要通过公网 HTTPS 稳定访问，成本保持在个人项目可长期承担的范围内；不以高并发或中国大陆节点为验收目标。

首选托管候选为 OCI Always Free；正式验收必须以实际取得的云主机和公网访问结果为准，不能把免费额度或实例容量视为已经获得。

DevGuide 的首发规范地址为 `devguide.into7ou.is-a.dev`，根地址 `into7ou.is-a.dev` 保留给未来个人主页；正式验收还需覆盖社区审核完成、DNS A/AAAA 记录生效、HTTPS 证书自动签发与续期，以及 GitHub OAuth 回调地址更新。

开发与生产使用两个独立 GitHub OAuth App。生产 App 的 Callback 必须精确等于 `https://devguide.into7ou.is-a.dev/login/oauth2/code/github`，关闭通配符且不启用 Device Flow；验收时还需确认本地 App 登录没有受到生产配置影响。

- PostgreSQL 使用 dev override 一次性重建后仍属于 skilllearningagents，容器名 techstack-postgres，卷为 skilllearningagents_pgdata，端口为 localhost:15432。
- 重建前后均为 tech_stacks=26、vector_store=44、users=1、user_tokens=1，证明本地开发数据未丢失。
- 后端第一次 prod 冒烟按设计拒绝本地弱 TOKEN_CIPHER_KEY；使用仅存在于测试进程的随机强密钥后成功启动。过程中还发现并修复两个多构造器 Service 缺少显式注入标记的问题。

- 验收结束后临时前后端容器均已删除，本地只保留健康的 PostgreSQL，日常 Docker Desktop 工作流不变。

## 已确认的容器验收目标

- Compose 中只有 `frontend`、`backend`、`postgres` 三个运行服务，均归属 `skilllearningagents`。
- `frontend` 使用 Caddy 服务 Vue 并自动管理 `devguide.into7ou.is-a.dev` 的 HTTPS。
- 主机仅开放 80/443 和运维所需的受限 SSH；后端与 PostgreSQL 端口不向公网发布。
- `/api`、OAuth、SSE 与 MCP 经 Caddy 转发，SSE 必须保持逐事件输出。
- GitHub Actions 在公开仓库运行完整测试，并生成可拉取的 AMD64/ARM64 GHCR 镜像。
- Pull Request 不发布镜像；镜像检查不得包含 `.env` 或生产密钥。
- OCI 通过人工执行 `docker compose pull` 与 `docker compose up -d` 更新，不依赖云端 SSH 自动部署。
- 本地 dev override 继续提供 `localhost:15432`，Maven/Vite 开发端口与现有 `.env` 不变。
- 使用 dev override 完成一次重建后，`techstack-postgres` 仍可在 Docker Desktop 中直接启动/停止，并继续挂载 `skilllearningagents_pgdata`。
- 首次正式发布使用 `v0.7.0`，前后端镜像标签一致且同时可由 Commit SHA 精确定位；生产 Compose 拒绝缺失 `IMAGE_TAG` 的部署。
- 生产环境实际运行的镜像摘要与发布记录一致，不通过 `latest` 或 `main` 隐式漂移。

## 已确认的公开访问验收目标

- 匿名用户可通过 `/api/v1/showcase/tech-stacks` 浏览数据库中已有技术栈及已收录详情。
- 公开详情允许使用缓存的 GitHub Top10；未知名称返回 404，不调用模型/Tavily、不动态转正、不写数据库。
- 动态发现、Agent 问答、联网补充和资料回写继续要求登录。
- 前端对需要生成访问的操作给出明确登录提示，不把后端 401 直接显示为普通加载失败。
- 匿名用户仍可在已加载清单中执行名称和分类筛选；无匹配时的动态搜索入口及 Agent 输入会提示 GitHub 登录。

## 已确认的生成准入验收目标

- 生产环境每个 GitHub 用户每 UTC 日最多执行 10 次 Agent 请求、20 次动态搜索，全站生成任务并发上限为 2；开发环境默认不限制。
- 超出用户配额或全站并发上限时返回 HTTP 429、稳定错误码和重试提示，不调用模型、Tavily、GitHub 或资料回写。
- 不同用户的日配额互不影响；UTC 日期切换后计数按规则重置。
- 并发许可在正常结束、异常和客户端取消 SSE 时均被释放，不发生永久占位。
- 业务测试通过替换生成准入接口模拟允许/拒绝，不依赖内存实现细节，为未来 Redis/队列实现保留兼容边界。

## 已确认的数据迁移验收目标

- 脱敏备份包含数据库结构、Flyway 历史、`tech_stacks` 与 `vector_store` 数据，不包含 `users`、`user_tokens` 数据。
- 恢复后技术栈与向量内容计数和抽样来源一致，生产 `users`、`user_tokens` 均为 0。
- 生产使用新生成的 `TOKEN_CIPHER_KEY`，本地密钥不复制到 OCI。
- 后端在恢复后的数据库上通过 Flyway 校验并正常启动；首次生产 OAuth 登录能够创建全新的用户和 Token。

## 已确认的生产备份验收目标

- 每日生产逻辑备份压缩后在 OCI 实例上完成公钥加密，Object Storage 中只出现密文对象。
- OCI 主机、Git 仓库、GitHub Actions 和对象存储中均不存在解密私钥；Bucket 保持私有并使用最小权限凭据。
- 自动保留 7 个日备份和 4 个周备份，清理策略不会删除当前恢复窗口内的全部可用副本。
- 备份过程无论成功或失败都不遗留明文数据库转储；失败能产生可观察的非零退出状态和日志。
- 从对象存储随机选取一个密文备份，在隔离临时数据库完成下载、离线解密、恢复、表计数与 PGvector 抽样查询。

## 已确认的可用性监控验收目标

- UptimeRobot 免费监控每 5 分钟分别检查 `https://devguide.into7ou.is-a.dev/` 与 `/api/health`，健康检查要求 HTTPS 2xx 且响应包含 `UP`。
- 监控请求不需要登录、不创建 Session，不触发模型、Tavily、GitHub 或数据库写入。
- OCI Monitoring 至少覆盖实例状态、CPU 高水位和磁盘容量风险，并通过 Notifications 邮件通知。
- 使用无破坏方式临时让专用健康检查返回不可用或暂停入口服务，验证故障邮件和恢复邮件均能收到；验收后恢复服务并复查公网访问。
- 告警账户、订阅邮箱与 OCI 标识不得写入 Git、镜像或公开文档。

## 已确认的发布与回滚验收目标

- 发布脚本或操作清单按“部署前备份 → 拉取同版本镜像 → 更新 → 健康/关键路径检查 → 记录成功版本”执行，任一步失败均不得标记发布成功。
- 使用非生产或隔离环境演练从当前标签切回上一成功标签，前后端始终作为一个发布单元切换。
- 回滚检查明确读取 Flyway 迁移兼容性；不兼容数据库变更会阻止单独应用回滚，并指向前向修复或备份恢复流程。
- 发布记录至少包含版本标签、Commit SHA、镜像摘要、发布时间、迁移版本和验收结果，不包含密钥。

## 已确认的生产日志验收目标

- 生产默认 `INFO`，SQL 与 Spring Security 调试日志关闭；本地开发日志行为不因生产配置改变。
- 自动化测试确认日志不包含完整提问、搜索词、原始 JSON/资料、Authorization、Cookie、OAuth Token、API Key 或数据库密码。
- 正常请求和异常请求可通过随机请求 ID 关联入口与后端日志，并记录接口模板、状态码、耗时和错误类型。
- 每个服务的应用日志同时满足最多 7 天和最多 50 MB 的轮转上限；重新部署和备份流程不要求保留这些日志。
- Docker 诊断日志使用受支持的轮转配置，验证旧文件可被自动淘汰且不会通过手工删除破坏正在写入的日志。
