# M7 部署 — 技术要点

> 阶段：M7 部署
> 创建日期：2026-09-04
> 更新日期：2026-09-05
> 状态：持续更新

## 1. API 鉴权与 CSRF

- **是什么**：认证确认“是谁”，授权决定“能访问什么”，CSRF 防止第三方页面借用浏览器 Session 发起状态变更。
- **在本项目中的作用**：业务 API 和 MCP 端点要求 GitHub 登录；Vue 在 POST 前取得 CSRF Token 并放入服务端指定的 Header。
- **面试可讲点**：只把接口改成 `authenticated()` 仍不够；Cookie Session 场景下，写操作还必须处理 CSRF。

## 2. Reactor Context 与 SecurityContextHolder

- **是什么**：Servlet SecurityContext 默认保存在 ThreadLocal，而 Reactor 流可能跨线程；Micrometer Context Propagation 在两种上下文之间建立桥接。
- **在本项目中的作用**：SSE 切到 `boundedElastic` 后，GitHub 工具仍能读取当前用户 Token，且线程复用不会串号。
- **面试可讲点**：`subscribeOn` 解决执行线程，不自动解决身份传播；需要注册 ThreadLocalAccessor、捕获 Reactor Context，并验证清理行为。

## 3. 阻塞边界

- **是什么**：`boundedElastic` 是 Reactor 为有上限的阻塞任务准备的调度器。
- **在本项目中的作用**：网页抓取、JDBC/向量检索、模型与工具调用不占用 Netty/并行事件线程。
- **面试可讲点**：重点不是“全部异步”，而是识别阻塞边界并用线程断言防止回归。

## 4. 版本化加密与密钥轮换

- **是什么**：密文前缀标记算法版本，历史密钥在有限窗口中只负责解密，新密钥负责所有新写入。
- **在本项目中的作用**：用户 GitHub Token 新写入使用 `Encryptors.stronger`；已有 CBC 密文仍可读取，用户再次登录后会用当前密钥覆盖。
- **面试可讲点**：直接替换加密算法会让存量数据不可读；版本化密文与双钥窗口是平滑迁移的关键。

## 5. 单实例部署边界

- **是什么**：实例内 Session 只能由当前进程可靠读取。
- **在本项目中的作用**：M7 首次部署固定一个后端副本，避免登录请求在多个实例间漂移。
- **面试可讲点**：单实例是明确的阶段性架构决策，不等于系统天然支持横向扩展；扩容前要共享 Session 和 authorized-client。

## 6. Compose 项目边界

- **是什么**：生产服务统一归属 `skilllearningagents` Compose 项目，使用项目默认网络进行容器间通信。
- **在本项目中的作用**：PostgreSQL/PGvector、后端、前端和反向代理共享一套可重复启动的编排；现有数据库继续使用原 `skilllearningagents_pgdata` 数据卷。
- **面试可讲点**：Compose 项目名会影响网络、容器和命名卷的资源名称；显式声明项目名能避免因目录重命名或从不同路径启动而意外创建第二套基础设施。

## 7. Caddy 前端入口

- **是什么**：前端生产镜像把 Vue 构建产物放入 Caddy，由同一容器提供静态页面、SPA 回退、自动 HTTPS 和反向代理。
- **在本项目中的作用**：公网只进入 `frontend` 的 80/443；API、OAuth、SSE 和 MCP 请求转发到 Compose 内网的 `backend:18080`，数据库不直接暴露。
- **面试可讲点**：把静态服务与入口代理合并可减少简历展示型单机部署的容器和证书运维；API 与 SPA 必须使用互斥 `handle`，否则 Caddy 指令排序可能让 `try_files` 抢先把 API 改写成 `index.html`。

## 8. 多架构镜像与人工发布门

- **是什么**：GitHub Actions 使用 Buildx 构建 AMD64/ARM64 镜像并发布到 GHCR，OCI 部署由人工执行 `pull` 和 `up -d`。
- **在本项目中的作用**：同一镜像既能在本地 x86 环境运行，也能部署到 OCI Ampere ARM；云主机不承担 Maven/Node 构建负载。
- **面试可讲点**：CI 自动验证和构建，CD 保留人工发布门；既展示流水线能力，又避免在早期把生产 SSH 凭据交给第三方 Runner。

## 9. 离机加密备份

- **是什么**：数据库先执行可移植的逻辑备份和压缩，再使用公钥在主机侧加密，把密文保存到私有对象存储；解密私钥离线保管。
- **在本项目中的作用**：Docker 命名卷负责本机持久化，OCI Object Storage 负责实例之外的灾备副本；`pg_dump` 标准输出直接进入 age 公钥加密，不在主机落明文，保留 7 个日备份和 4 个周备份。
- **面试可讲点**：备份成功不等于可恢复。方案同时区分首次脱敏迁移与生产全库灾备，并通过临时数据库恢复演练验证备份链路。

## 10. 生成准入与容量扩展缝

- **是什么**：生成请求在进入模型、搜索和写回链路前，先经过用户日配额与全站并发闸门；生产超限返回 429，开发默认关闭限制。
- **在本项目中的作用**：单实例阶段使用内存计数保护个人 API 额度，但业务服务只依赖准入接口，不直接持有计数器或信号量。
- **面试可讲点**：当前 10/20 次日配额和全站并发 2 是成本边界，不是吞吐能力上限的永久设计。未来可以把状态迁移到 Redis、在准入后增加队列，并配合共享 Session 扩展多实例。

## 11. 外部探测与内部资源告警

- **是什么**：UptimeRobot 从云厂商外部验证 HTTPS 页面和 `/api/health`，OCI Monitoring 监测虚拟机 CPU、磁盘与实例状态并通过 Notifications 告警。
- **在本项目中的作用**：外部探测回答“面试官是否真的能访问”，云内指标回答“不可用是否由主机资源引起”；两者不调用模型和搜索服务。
- **面试可讲点**：容器显示 running 不代表公网可用。DNS、TLS、入口代理、后端和主机资源需要从不同观察位置验证，并通过故障/恢复演练证明告警链路可用。

## 12. 不可变发布与数据库回滚边界

- **是什么**：生产 Compose 固定同一 `IMAGE_TAG` 的前后端不可变镜像，Commit SHA 保留构建追溯；`latest`/`main` 不参与生产版本选择。
- **在本项目中的作用**：`v0.7.0` 作为首次正式部署，发布前备份、发布后检查，并保存上一成功标签用于快速恢复。
- **面试可讲点**：镜像回滚不等于数据库回滚。只有迁移向后兼容时才能单独切回旧应用；不兼容迁移必须前向修复或恢复经验证的部署前备份。

## 13. 短期日志与数据最小化

- **是什么**：生产日志采用数据最小化和双条件轮转，每个服务最多保留 7 天或 50 MB，先达到者触发旧日志清理。
- **在本项目中的作用**：Caddy 为请求生成 UUID、覆盖客户端伪造值并转发给后端；两端用同一 ID 关联，同时移除提问、搜索词、查询参数、Header、Token、Cookie、OAuth 信息及原始资料内容。
- **面试可讲点**：日志不是越多越好。单机演示站优先控制隐私与磁盘风险；未来接入集中日志时复用既有字段和脱敏边界，而不是重新暴露敏感数据。
