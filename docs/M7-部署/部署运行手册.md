# M7 部署运行手册

> 阶段：M7 部署
> 创建日期：2026-09-05
> 更新日期：2026-09-05
> 状态：本地构建、数据脱敏恢复演练已通过；OCI、DNS、OAuth、GHCR 与公网监控等待人工配置

## 1. 不影响本地开发的边界

- 日常只启动 PostgreSQL：在 Docker Desktop 启停 techstack-postgres，或运行 ./scripts/start-postgres.ps1。
- docker-compose.yml 中前后端带 app profile，普通 docker compose up -d 不会自动启动它们。
- 本地数据库仍映射 localhost:15432，数据卷仍为 skilllearningagents_pgdata。
- OCI 使用独立 .env、独立数据库卷和生产 GitHub OAuth App，不修改本机 .env。

## 2. GitHub Actions 与 GHCR

1. 把当前分支通过 Pull Request 合入 main。PR 只运行测试和双架构镜像构建，不发布镜像。
2. main 构建成功后，GHCR 生成 main 与 sha-... 标签；推送 v0.7.0 Git tag 后生成同名不可变标签。
3. 首次生成 Package 后，在 GitHub 个人主页进入 Packages，分别打开 devguide-backend、devguide-frontend，在 Package settings 中把可见性改为 Public。
4. OCI 只拉取 v0.7.0 或 sha-...，不以 main 作为正式部署版本。

这是当前唯一预期的 GitHub 人工介入点。若 Actions 因 Package 权限失败，先检查仓库 Actions 的 Read and write permissions 与 Package 归属，不向仓库添加 PAT。

## 3. OCI 主机最低准备

- 首选 OCI Always Free ARM64 实例；若无法取得容量，可原样迁移到任意支持 Docker Compose 的 Linux VPS。
- 安装 Docker Engine、Compose plugin、curl。备份还需要 age、OCI CLI 和 jq。
- OCI Security List/NSG 与主机防火墙仅开放 TCP 80、443，以及限制来源 IP 的 SSH；不要开放 18080、5432 或 15432。
- 把仓库放到 /opt/devguide，生产环境文件放到 /etc/devguide/devguide.env，执行 chmod 600 /etc/devguide/devguide.env。
- 从 .env.production.example 复制配置；生产必须生成新 POSTGRES_PASSWORD 和至少 32 个随机字符的 TOKEN_CIPHER_KEY，不得复制本地值。

配置校验：

    IMAGE_TAG=v0.7.0 docker compose --env-file /etc/devguide/devguide.env \
      -f docker-compose.yml -f docker-compose.prod.yml --profile app config --quiet

## 4. 域名与 GitHub OAuth

1. 完成 into7ou.is-a.dev 社区申请，将 devguide.into7ou.is-a.dev 的 A/AAAA 记录指向 OCI 公网地址。
2. 新建 GitHub OAuth App DevGuide Production：
   - Homepage URL：https://devguide.into7ou.is-a.dev
   - Callback URL：https://devguide.into7ou.is-a.dev/login/oauth2/code/github
   - 不启用 Device Flow，不使用通配符。
3. Client ID/Secret 只写入 /etc/devguide/devguide.env。
4. DNS 生效后由 Caddy 自动申请证书；查看 docker compose logs frontend 确认证书成功。

## 5. 首次脱敏内容迁移

在本机、仓库外生成迁移包：

    .\scripts\export-sanitized-content.ps1 -OutputPath D:\private\devguide-sanitized.dump
    .\scripts\verify-sanitized-restore.ps1 -BackupPath D:\private\devguide-sanitized.dump

验证脚本会创建并删除隔离 PostgreSQL 容器，要求 tech_stacks、vector_store、Flyway 与 PGvector 完整，同时 users、user_tokens 都为 0。通过后才把迁移包安全传到 OCI；不得提交 Git 或 Actions Artifact。

OCI 首次恢复顺序：

    docker compose --env-file /etc/devguide/devguide.env -f docker-compose.yml up -d postgres
    docker cp /secure/path/devguide-sanitized.dump techstack-postgres:/tmp/devguide-sanitized.dump
    docker exec techstack-postgres sh -lc 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --no-owner --no-privileges /tmp/devguide-sanitized.dump'
    docker exec techstack-postgres rm -f /tmp/devguide-sanitized.dump

恢复后先查四张表计数，再启动后端。首次生产 OAuth 登录应创建全新用户和用生产新密钥加密的 Token。

## 6. 加密生产备份

在一台离线可信设备生成 age 密钥：

    age-keygen -o devguide-backup.agekey
    age-keygen -y devguide-backup.agekey

- 私钥 devguide-backup.agekey 至少保存两份离线副本，绝不上传 OCI、GitHub 或仓库；丢失后历史备份无法恢复。
- 只把第二条命令输出的 age1... 公钥写入 /etc/devguide/backup.env 的 AGE_RECIPIENT。
- 创建私有 OCI Object Storage Bucket 和只允许该 Bucket 对象列举、上传、读取、删除的最小权限凭据。
- 从 scripts/ops/backup.env.example 复制配置到 /etc/devguide/backup.env 并设为 600。

手动演练：

    set -a
    source /etc/devguide/backup.env
    set +a
    bash scripts/ops/backup-production.sh

脚本将 pg_dump 标准输出直接送入 age，不在主机落明文；保留最新 7 个 daily/ 对象，并在 UTC 周日保留最新 4 个 weekly/ 对象。

定时器：

    sudo cp deploy/systemd/devguide-backup.* /etc/systemd/system/
    sudo systemctl daemon-reload
    sudo systemctl enable --now devguide-backup.timer
    systemctl list-timers devguide-backup.timer
    journalctl -u devguide-backup.service

恢复属于破坏性操作。停止后端并确认目标后，下载密文到隔离环境，设置 ALLOW_DATABASE_RESTORE=yes，再运行 bash scripts/ops/restore-production.sh <密文> <离线私钥>。至少完成一次临时数据库恢复与 PGvector 抽样。

## 7. 发布、验证与回滚

首次发布：

    set -a
    source /etc/devguide/backup.env
    set +a
    RELEASE_COMMIT_SHA=<完整提交SHA> bash scripts/ops/deploy.sh v0.7.0 /etc/devguide/devguide.env

流程固定为：部署前加密备份、拉取前后端同标签镜像、更新三容器、检查首页/健康/匿名展示接口、记录成功版本。另按 发布记录模板.md 记录两个镜像摘要、Flyway 版本、OAuth 和 SSE 人工验收。

仅在确认现有数据库兼容旧应用后回滚：

    ROLLBACK_DB_COMPATIBLE=yes bash scripts/ops/rollback.sh <上一成功不可变标签> /etc/devguide/devguide.env

存在不兼容 Flyway 迁移时脚本默认拒绝回滚；采用前向修复，或经明确确认恢复部署前备份。

## 8. 监控人工配置

UptimeRobot 免费计划建立两个 5 分钟 HTTP(S) Monitor：

- https://devguide.into7ou.is-a.dev/：要求 HTTPS 2xx。
- https://devguide.into7ou.is-a.dev/api/health：要求 HTTPS 2xx 且响应包含 UP。

OCI Monitoring/Notifications：

- 创建邮件 Topic 并完成订阅确认。
- 实例状态非 Running 立即告警。
- CPU 使用率连续 15 分钟高于 85% 告警。
- 磁盘使用率连续 15 分钟高于 80% 告警；若默认指标没有磁盘使用率，安装 Oracle Cloud Agent 的 Compute Instance Monitoring/Custom Logs 插件后配置。
- 通过暂停 frontend 或临时阻断专用健康检查执行一次无破坏演练，确认故障与恢复邮件均到达，随后恢复并再次运行验证脚本。

监控只能访问首页和 /api/health，不得请求生成、搜索或 GitHub API。

## 9. 日志

- Caddy 访问日志写入容器临时目录，移除全部请求 Header、移除 URL 查询字符串、掩码 IP，并加入 Caddy UUID；同一 UUID 通过内部 Header 传给后端。
- 后端只接受合法 UUID 形式的代理请求 ID，响应返回 X-Request-ID；记录方法、路径、状态、耗时和错误类型，不记录正文、查询参数或认证 Header。
- Caddy 和后端应用日志最多 7 天、约 50 MB；Docker local 日志驱动另按 10 MB × 5 文件轮转。
- 日志不在命名卷中，容器重建即可丢弃；不要直接删除 Docker 正在写入的底层日志文件。
