## 问题 1：PowerShell 读 .env 编码错误导致 GITHUB_TOKEN 没加载（blocking，已修）

- **现象**：`fetchReadme` 全部 403「rate limit exceeded for 103.62.49.178」（未认证限流）。
- **根因**：`run-backend.ps1` 用 `Get-Content` 读 UTF-8 的 `.env` 时没指定编码，中文注释行 `# GitHub（应用级 Token，仅搜公开仓库）` 的 UTF-8 字节被按 GBK 错读，**吞掉了换行符**，导致 `GITHUB_TOKEN` 行与上一行合并成一行，且合并后以 `#` 开头 → 被当成注释跳过。
- **解决**：`Get-Content` 加 `-Encoding UTF8`。
- **踩坑点**：DEEPSEEK/DASHSCOPE 恰好在中文注释后没触发合并，只有最后一个 `GITHUB_TOKEN` 中招——这种编码 bug 隐蔽且只影响特定行，很难发现。

## 问题 2：curl 测试命令的 JSON 引号被 PowerShell 吞掉（测试方法问题）

- **现象**：learn 接口报 500 `JSON parse error: Unexpected character 't'`。
- **根因**：`curl.exe -d $body` 时 PowerShell 把 JSON 双引号弄丢，请求体变成坏 JSON。
- **解决**：改用 `Invoke-RestMethod -Body (哈希表 | ConvertTo-Json)` 发送。
- **踩坑点**：这是测试脚本问题，不是代码 bug。

## 问题 3：部分 GitHub README 返回 404（正常情况）

- **现象**：抓 README 时部分仓库 404（如 awesome-flask、trape 等）。
- **根因**：这些仓库已删除/改名/无 README，但 topic 搜索结果里仍出现。
- **处理**：代码已捕获并跳过（优雅降级），不影响整体入库。
- **踩坑点**：外部数据源的脏数据是常态，不该让单个失败拖垮整个入库。

## 问题 4：通用异常处理器未记日志（已修）

- **现象**：learn 接口 500 时看不到具体异常。
- **解决**：`GlobalExceptionHandler` 的兜底 handler 加 `log.error`。
- **踩坑点**：兜底异常处理一定要记日志，否则线上排查无从下手。

## 问题 5：对抗式代码审查发现（14 条，已修复核心缺陷）

独立 subagent 审查结论：**无崩溃级 bug，但有一个破坏 RAG 语义的高危缺陷**。已修复：

| 严重度 | 问题 | 修复 |
|---|---|---|
| 高 | 空/全失败入库仍置 `ragIngestedAt`，永久「假已入库」 | `chunks.isEmpty()` 时不置标记，返回 0 |
| 高 | 先删旧数据再抓取，抓取失败即清空向量库 | 改为「先抓取成功 → 再删旧 → 再写入」 |
| 中 | `topRepos` 无 try/catch，限流异常冲出 ingest | 包 try/catch 降级跳过 |
| 中 | 空文本/空列表未校验就进 embedding | 过滤 null/blank，空 chunks 短路 |
| 中 | `updateById` 整行回写（并发丢更新 + updated_at 失真） | 改用 `LambdaUpdateWrapper` 只更新 `rag_ingested_at` |
| 中 | retrieved 为空仍调 DeepSeek（幻觉 + 浪费成本） | 空检索返回降级文案 |
| 中 | 并发首次 learn 双入库竞态 | 按技术栈名加 `ReentrantLock` |
| 中 | 非法 JSON 请求体返回 500 而非 400 | 加 `HttpMessageNotReadableException` → 400 |
| 低 | question 无长度上限 | 截断到 500 字 |
| 低 | `extractCitations` 强转 String 可能 CCE | 用 `instanceof` 过滤 |

## 问题 6：第二轮审查（通过，无 blocking）

第二轮独立审查结论：**无 blocking、无高危**，上轮 10 项修复方向全部正确。本轮补齐：
- 引用编号与去重 citations 错位 → 去掉 `[i]` 编号，改在每段标注「来源 URL」，与 citations 列表一致
- topRepos 降级不完整 → `TechStackService` 两处调用统一 `safeTopRepos` 降级为空列表
- 成功入库 / add 失败 / 幂等跳过 三个核心用例补测试
- 改用显式 `@Update` SQL（`markIngested`）只更新 `rag_ingested_at` 单列（比 lambda 包装器更可测、语义更清晰）
- `similarityThreshold(0.2)` 语义经反编译验证正确（0.2 为宽松下限，已注释说明）

> 剩余低风险（可接受，不影响正确性）：`ingestLocks` map 只增不减、`requireStack` 重复查询、Mockito agent 环境依赖。
