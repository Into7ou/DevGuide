# M3 Agent 业务 — 技术要点（面试可讲）

> 每个点用「是什么 → 作用 → 为什么」三句话讲清，点到为止。

## 1. RAG（检索增强生成）
- **是什么**：让大模型基于「检索到的资料」回答，而不是只靠训练时记住的知识。
- **作用**：把官方文档 + GitHub README 作为上下文，让 DeepSeek 生成有依据的学习引导。
- **为什么**：解决大模型「幻觉」和「知识过时」——它不会瞎编，而是引用真实资料。

## 2. 文档切分 + 向量化
- **是什么**：把长文档切成小块（TokenTextSplitter），每块用通义转成向量。
- **作用**：把文档变成向量库里的一条条「知识片段」。
- **为什么**：整篇文档太长喂不进去，切块后才能精确检索到相关段落。

## 3. 向量检索（PGvector + 元数据过滤）
- **是什么**：把用户问题也转成向量，找最相似的片段；用 metadata 过滤只看当前技术栈。
- **作用**：精准找到和问题相关的资料片段。
- **为什么**：向量相似度是「语义搜索」，比关键词匹配更聪明。

## 4. 带引用的生成
- **是什么**：把检索到的片段拼进 prompt，让 DeepSeek 基于它们回答，并返回来源 URL。
- **作用**：生成带引用的学习路线，可溯源。
- **为什么**：用户能验证答案来源，这正是 RAG 的价值。

## 5. 技术栈作用一览
| 技术 | 作用 |
|---|---|
| RAG 流程 | 切分 → 向量化 → 检索 → 生成 |
| TokenTextSplitter | 文档切块 |
| 通义 embedding | 文本转向量 |
| PGvector | 向量存储 + 相似度检索 |
| DeepSeek | 基于资料生成学习引导 |
