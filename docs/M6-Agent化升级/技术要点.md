# M6 Agent 化升级 — 技术要点（面试可讲）

> 所属阶段：M6 Agent 化升级
> 更新日期：2026-09-04
> 状态：Agent 主流程已完成；响应式安全上下文与阻塞线程边界已在 M7 前置处理中补齐

> 每个点用「是什么 → 作用 → 为什么」三句话讲清。

## 1. Function Calling（工具调用）
- **是什么**：让 LLM 不只会「说话」，还能「调用函数」——把后端能力（搜 GitHub、抓 README、联网搜索、向量检索）注册成工具，模型按需调用。
- **作用**：把 Agent 从「资料整合」升级为「自主执行」，能实时取真实数据而非凭空生成。
- **为什么**：LLM 的知识有截止时间、会编造；Function Calling 让它「需要时调用工具拿真实数据」，这是 Agent 的基石。

## 2. @Tool 注解 + MethodToolCallbackProvider
- **是什么**：用 `@Tool` 注解标注方法，`MethodToolCallbackProvider` 自动把方法转成 `ToolCallback` 注册进 `ChatClient`。
- **作用**：把普通 Service 方法零侵入地暴露为 LLM 可调用的工具。
- **为什么**：声明式、可复用——同一工具既能给单 Agent 用，也能转成 MCP 规范；不用写一堆适配代码。

## 3. ReAct Agent（自主编排）
- **是什么**：模型「思考 → 调用工具 → 观察结果 → 再思考」循环，自主决定调用哪些工具、什么顺序、何时停止。
- **作用**：用户只说「React 怎么入门」，Agent 自己决定「先联网找文档 → 搜 GitHub 项目 → 抓 README → 生成」，无需硬编码流程。
- **为什么**：固定链路只能处理预设场景；ReAct 让 Agent 应对开放问题，是「精准搜集 Agent」的核心能力。Spring AI 里由 `ChatClient` + `ToolCallingManager` 在框架层完成循环。

## 4. SSE 流式输出
- **是什么**：服务端把生成结果按 token 分块推给前端（`text/event-stream`），前端实时渲染。
- **作用**：用户看到「逐字生成」，不用等几十秒空白页，体验大幅提升。
- **为什么**：Agent 要调多个工具、耗时数十秒，若同步返回，用户只能干等；流式让过程可见、可中断，是 LLM 应用的标配。

## 5. 多智能体（两段式协作）
- **是什么**：拆成两个 Agent——「资料搜集 Agent」（带工具，负责搜）和「讲解生成 Agent」（不带工具，负责讲），编排器串联。
- **作用**：职责单一，搜集和讲解各司其职，prompt 更聚焦、输出更稳定。
- **为什么**：单 Agent 又要搜又要讲，prompt 臃肿、易出错；拆分后每个 Agent 目标清晰，符合「单一职责」，也便于独立优化替换。

## 6. MCP（Model Context Protocol）
- **是什么**：AI 应用与「外部工具/数据源」之间的开放协议，类似「AI 界的 USB 接口」，Server 暴露工具、Client 连接调用。
- **作用**：本项目自建 MCP Server 把 GitHub 工具按 MCP 规范暴露（SSE 端点 `/sse`），任何支持 MCP 的客户端都能接入，不必绑死 Spring AI。
- **为什么**：工具不再被某个框架独占，跨框架复用；这是 2024-2025 年 AI 工程的热点协议，面试很有分量。

## 7. Tavily 联网搜索
- **是什么**：第三方联网搜索 API，把自然语言 query 转成带摘要和链接的搜索结果。
- **作用**：补足 LLM 知识截止的问题，让 Agent 搜到最新官方文档、教程、动态。
- **为什么**：RAG 只能搜「已入库」的文档，联网搜索覆盖「未入库」的实时信息，两者互补，是「可扩展 RAG」的关键一环。

## 8. 响应式安全上下文与阻塞边界
- **是什么**：把 Servlet `SecurityContext` 捕获到 Reactor Context，并在 `boundedElastic` 工作线程恢复；单 Agent 和多智能体阻塞链路使用统一调度边界。
- **作用**：异步工具调用仍能识别当前登录用户，同时避免模型、联网和数据库阻塞操作占用 Reactor 事件循环线程。
- **为什么**：线程切换会丢失普通 ThreadLocal，而阻塞 event loop 会拖慢同进程全部请求；身份传播与线程隔离需要一起验证。

## 9. 技术栈作用一览
| 技术 | 作用 |
|---|---|
| `@Tool` / `MethodToolCallbackProvider` | 把方法暴露为 LLM 工具 |
| `ChatClient` + `ToolCallingManager` | ReAct 自主编排 |
| `Flux<String>` + `text/event-stream` | SSE 流式输出 |
| ResearchAgent + GuideAgent | 多智能体两段式协作 |
| `@McpTool` + MCP Server/Client | MCP 协议两端 |
| Tavily | 联网搜索 |
| DeepSeek Function Calling | 模型工具调用能力 |
| Reactor Context + Micrometer Context Propagation | 跨异步线程传递并清理登录上下文 |
| `boundedElastic` | 隔离模型、联网和数据库等阻塞调用 |
