## 已解决的问题

### 1. `defaultTools()` 与 `defaultToolCallbacks()` 用错导致启动失败

- **现象**：后端启动报 `IllegalStateException: No @Tool annotated methods found in MethodToolCallback{...}. Did you mean to pass a ToolCallback or ToolCallbackProvider? If so, you have to use .toolCallbacks() instead of .tool()`。
- **根因**：`ChatClient.Builder` 有两个易混淆方法：
  - `defaultTools(Object...)`：接收**带 @Tool 注解的对象**，内部用 `MethodToolCallbackProvider` 重新解析。
  - `defaultToolCallbacks(ToolCallback...)`：接收**已构造好的 ToolCallback 数组**。
  我把 `MethodToolCallbackProvider.getToolCallbacks()` 返回的 `ToolCallback[]` 传给了 `defaultTools()`，导致 Spring 把它当「对象数组」再次解析，报错。
- **修复**：统一改为 `defaultToolCallbacks(agentToolCallbacks)`。
- **踩坑点**：Spring AI 1.1.0 里 `defaultTools` 和 `defaultToolCallbacks` 语义完全不同，命名相似极易混用。

### 2. MCP Client 同进程自连 SSE 导致启动时序冲突

- **现象**：配置 `spring.ai.mcp.client.sse.connections` 连接本应用自己的 `/sse` 端点后，启动失败，报 `Client failed to initialize by explicit API call`（20s 超时 `ConnectException`）。
- **根因**：Spring 启动时，`toolCallbackResolver`（`ToolCallingManager` 的依赖）会立即收集所有 `ToolCallbackProvider`（含 MCP 的 `SyncMcpToolCallbackProvider`），触发 `mcpSyncClients` 创建并 `initialize()` 连接 `localhost:8080/sse`。但此时 Web 容器还没启动，连接必然失败。
- **处理**：MCP Client 默认禁用（`spring.ai.mcp.client.enabled: false`），避免启动期强制连接；MCP Server 端照常暴露（`Registered tools: 2`）。演示「MCP Client 连接外部 MCP Server」时再启用并配置 connections（已在 yml 注释说明）。
- **结论**：同一进程「Server 自连 Client」在 Spring 启动期天然时序冲突，不是配置错误，而是架构上不合适；MCP 的规范用法是 Server 与 Client 分离部署。

### 3. SSE 接口 `Invalid request body`（定位：curl 引号问题，非后端 Bug）

- **现象**：用 `curl.exe -d $body` 测 SSE 接口返回 `{"error":"Invalid request body"}`，一度怀疑后端 body 解析。
- **定位**：改用 PowerShell `Invoke-WebRequest` + UTF8 字节测同一接口，正常返回。确认是 **curl.exe 在 PowerShell 下的引号转义**把 JSON body 弄坏了，不是后端问题。
- **经验**：Windows 下 PowerShell 调 curl 传 JSON 要小心引号；验证后端优先用 `Invoke-WebRequest` 或 `[System.Net.HttpWebRequest]`。

### 4. Tavily 未配置 key 时 401

- **现象**：`webSearch` 工具调用报 `tavily search error: Server error, code: 401`。
- **根因**：`TAVILY_SEARCH_API_KEY` 尚未配置（等用户注册 Tavily 提供 key）。
- **现状**：`WebSearchTools` 已捕获异常并返回错误文本，Agent 会降级用其他工具继续，不影响整体流程；待 key 配置后联网搜索生效。

## 首页搜索框「任意技术栈联网查询」补漏（用户反馈）

- **问题**：M6 验收标准要求「自由输入任意技术栈」，但首页搜索框仍只做本地 `filterStacks` 过滤预置清单，输入未收录技术栈（如 Astro）时只显示「没有匹配」，无法触发联网查询。后端 `getOverview` 对任意技术栈早有兜底（返回 GitHub Top10），详情页也接了多智能体联网搜索，缺口仅在首页入口。
- **修复**：`StackListView.vue` 增加「联网查询」入口——输入非空且无本地匹配时，展示「联网查询「XXX」」按钮 + 回车跳转到 `/stack/:name` 详情页，由详情页走「GitHub Top10 + 多智能体联网搜索」完整链路。
- **验证**：未收录技术栈 "Astro" 端到端跑通——详情返回 name=Astro + 10 个 GitHub Top10（withastro/astro 等），多智能体流式生成学习引导（11026 字符，换行正常）。
