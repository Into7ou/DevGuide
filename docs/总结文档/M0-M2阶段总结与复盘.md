# DevGuide — M0~M2 阶段总结与复盘

> 面向校招面试：每个技术点「一句话说清是什么、作用、为什么」，不深入源码级细节。

---

## 一、项目全貌

**一句话定位**：DevGuide 是一个面向开发者的技术栈学习 Agent——用户查询某技术栈，即可获得**官方文档入口 + GitHub star Top10 开源项目 + 基于资料的 LLM 学习引导**。

**和普通搜索页的区别**：不是「搜出来给你看」，而是把「官方文档 + 优质开源项目」作为上下文喂给大模型，生成**有依据、可溯源**的学习路线——这就是 RAG（检索增强生成）的落地。

**当前进度**：M0 基座验收 ✅ → M1 骨架搭建 ✅ → M2 数据层 ✅（已打通「查技术栈 → 拿官方文档 → 拉 GitHub Top10」）。

---

## 二、需求分析与关键决策

| 决策 | 方案 | 一句话理由 |
|---|---|---|
| 构建方式 | 基于开源项目改造 | 快速起步、复用成熟骨架 |
| 前端 | Vue3 | 生态成熟 |
| 后端 | Java 21 + Spring Boot 3 | 有 Spring AI Alibaba 支持 |
| LLM | DeepSeek | 国内可用、性价比高 |
| embedding | 阿里云通义 | DeepSeek 不提供 embedding |
| 数据库 | PostgreSQL + PGvector | 一个库存业务数据 + 向量 |
| 登录 | GitHub OAuth（预留注册） | 目标用户是程序员，顺带绑 Token |
| 部署 | Docker Compose | 一键起前后端 + 数据库 |

**两次重要转向**（体现「选型根据事实修正」）：
1. **基座**：careermate 等中文 AI 教学项目普遍没有开源 License（有法律风险）→ 改用 spring-ai-alibaba 官方 examples（Apache-2.0，合法、技术栈匹配）。
2. **数据库**：MySQL 用不了 PGvector（它是 PostgreSQL 专属扩展），做向量要么 MySQL+Milvus（多一个组件）→ 改用 PostgreSQL + PGvector（一个库搞定，部署简单）。

## 三、M0 基座验收

**做了什么**：调研候选基座 → 验证 License（发现全不达标）→ 转向 spring-ai-alibaba 官方 examples → 确认本地环境就绪。

**关键技术点**：
- 开源 License：改造前必须确认基座有合法许可，否则有法律风险。
- 选官方框架 examples 当基座：合法、稳定，业务层自研占比高。

---

## 四、M1 骨架搭建

**做了什么**：搭 backend + frontend + docker-compose + .env；接入 DeepSeek（对话）+ 通义（embedding）；打通 PostgreSQL+PGvector。

**关键技术点**：
- Spring AI Alibaba：统一接入不同大模型，换模型只改配置。
- 对话模型 vs 向量模型分工：DeepSeek 生成文本，通义做向量化（因为 DeepSeek 无 embedding）。
- 多模型共存：注入具体模型类，避免 Spring 多 Bean 冲突。
- 密钥外置：`.env` + gitignore，不硬编码。

---

## 五、M2 数据层

**做了什么**：Flyway 建表 + 21 个技术栈种子数据；MyBatis-Plus 查询；RestClient 拉 GitHub Top10 + 缓存；Jsoup 抓文档关键页。

**关键技术点**：
- MyBatis-Plus：BaseMapper 免写 CRUD，复杂查询自定义 SQL。
- Flyway：数据库结构版本化，换环境可自动复现。
- RestClient：调 GitHub API，自动 JSON 反序列化。
- Caffeine + 缓存：缓存 Top10 结果，应对 GitHub 搜索限流。
- Jsoup：抓官方文档关键页转纯文本（RAG 备料）。
- GitHub Search API：按 topic + star 排序拉 Top10。
- JSONB + TypeHandler：存关键页 URL 数组。

**代码质量**：写了 4 个单元测试，并让独立 reviewer 做对抗式代码审查，抓到并修复了别名通配符注入、JSONB 写路径类型不匹配、HTTP 无超时等真实问题（无 blocking bug）。

## 六、简历写法建议

> **DevGuide（全栈）** — Java 21 / Spring Boot 3 / Spring AI Alibaba / Vue3 / PostgreSQL+PGvector / MyBatis-Plus / Docker
> - 基于 Spring Boot + Vue3 开发「技术栈学习」Agent 应用：用 RestClient 调 GitHub Search API 拉取技术栈 star Top10 开源项目，Caffeine 缓存应对搜索限流。
> - 接入 DeepSeek（对话）与阿里云通义（embedding）双模型，用 Spring AI Alibaba 实现多模型共存；PostgreSQL + PGvector 统一承载业务数据与向量存储，为 RAG 做准备。
> - 用 Jsoup 抓取官方文档关键页；自定义 TypeHandler 处理 JSONB 列；建立全局异常处理与单元测试，并通过对抗式 Code Review 保证质量。

## 七、面试高频问题（自测）

**AI 相关**
1. RAG 是什么？为什么需要它？（减少幻觉 + 知识过时 + 可溯源）
2. 为什么对话用 DeepSeek、向量化用通义？（DeepSeek 无 embedding）
3. 一个应用接多个模型，怎么避免冲突？（注入具体类而非泛型接口）

**数据相关**
4. 为什么 PostgreSQL + PGvector 而不是 MySQL？（PGvector 是 PG 专属扩展，一个库够用）
5. Flyway 是干嘛的？（数据库结构版本化）
6. JSONB 和 VARCHAR 存 JSON 有啥区别？（JSONB 是真正的 JSON 类型，可索引）

**缓存 / HTTP**
7. @Cacheable 的作用？你的场景为什么用它？（应对 GitHub 搜索限流）
8. 缓存穿透/击穿/雪崩分别是什么？（一句话各举一例即可）
9. RestClient 和 RestTemplate 的区别？（RestClient 更新、更简洁）

**工程**
10. 你的后端是怎么分层的？（controller → service → mapper/client）
11. 密钥怎么管理？（.env + gitignore，不硬编码）
12. 你怎么保证代码质量？（单元测试 + 代码审查）

## 八、下一阶段

- **M3 Agent 业务**（核心）：检索聚合 → RAG 入库（通义 embedding + PGvector）→ DeepSeek 生成学习引导（带引用）。
- **M4 前端**：搜索/清单、文档+Top10 卡片、学习引导对话。
- **M5 用户体系**：GitHub OAuth 登录 + Token 绑定。
- **M6 部署**：Docker Compose 全栈编排。
- **M7 联调验收**：端到端跑通、交付。

> M3 的 RAG 是项目灵魂——到时候你会真正理解「切分 → 向量化 → 检索 → 生成」这条链路，这也是面试最能拉开差距的部分。
